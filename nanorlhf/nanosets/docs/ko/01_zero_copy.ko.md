# Zero-Copy
이 문서에서는 Zero-copy에 대해 설명합니다.

## 1. Zero-Copy는 무엇인가요?

우리가 보통 Python에서 데이터를 다룰 때 데이터를 복사해서 새로운 객체를 만드는 일이 자주 발생합니다. 
예를 들어, 리스트, 문자열, 바이트 객체 등을 슬라이싱할 때, Python은 원본의 데이터를 복사하여 새로운 메모리 공간에 이를 저장합니다.

예를 들어 다음과 같은 코드를 생각해 봅시다.

```python
a = b"hello world"
b = a[0:5]  # b'hello'라는 새로운 바이트 객체가 생성됩니다.
```

이 경우에, `b`는 `a`의 일부를 복사한 새로운 객체이며 서로 다른 메모리 공간을 차지합니다.
우리는 이를 `id()` 함수를 통해 확인할 수 있습니다.

```python
print(id(a))  # 4387007312
print(id(b))  # 4387006544
```

하지만 사실 `b`의 데이터는 `a`의 데이터의 일부이므로 `hello`라는 동일한 값이 메모리에 두개 존재하게 됩니다.
이를 보다 더 똑똑하게 처리할 수는 없을까요? 

이를 해결하기 위해 우리는 `memoryview`를 사용할 수 있습니다.
`memoryview`는 원본 데이터를 복사하지 않고도 데이터의 일부를 참조할 수 있게 해줍니다.
따라서 참조본이 원본과 동일한 메모리 공간을 사용하게 됩니다.

```python
a = b"hello world"
b = memoryview(a)[0:5]  # b'hello'라는 memoryview 객체가 생성됩니다.
```

이 경우에, `b`는 `a`의 일부를 복사하지 않고 원본 데이터를 참조하기 때문에 동일한 메모리 공간을 사용합니다.

```python
print(id(a))  # 4387007312
print(id(b.obj))  # 4387007312
```

우리는 이렇게 원본 데이터를 복사하지 않고 참조하는 방식을 "Zero-Copy"라고 부르며,
이는 대용량 데이터를 처리할 때 매우 유용할 수 있습니다.

## 2. Arrow-like 시스템에서 Zero-Copy는 왜 중요한가요?
Arrow와 같은 컬럼형 데이터 포맷에서는 대용량 데이터를 효율적으로 처리하는 것이 중요합니다.
Zero-copy는 이러한 시스템에서 데이터의 복사 비용을 줄이고 성능을 향상시키는 데 중요한 역할을 합니다.
예를 들어, 대용량의 테이블 데이터를 처리할 때, 각 컬럼의 데이터를 복사하지 않고 참조할 수 있다면 메모리 사용량과 처리 시간을 크게 줄일 수 있습니다.

## Zero-copy: 3줄 요약
- Zero-copy는 데이터를 복사하지 않고 참조하는 방식을 의미합니다.
- Python의 `memoryview`를 사용하면 원본 데이터를 복사하지 않고도 데이터의 일부를 참조할 수 있습니다.
- Arrow와 같은 시스템에서 Zero-copy는 대용량 데이터 처리의 효율성을 높이는 데 중요합니다.
