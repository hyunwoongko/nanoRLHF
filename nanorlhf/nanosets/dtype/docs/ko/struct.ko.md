# struct 모듈

파이썬의 `struct` 모듈은 **파이썬 값(정수, 실수 등)을 정해진 규격의 바이너리(bytes)로 변환(pack)** 하거나, **바이너리 데이터를 다시 값으로 해석(unpack)** 할 때 사용하는 표준 라이브러리입니다. 파일 포맷, 네트워크 프로토콜, 바이너리 로그처럼 "바이트 단위로 정해진 레이아웃"을 다뤄야 할 때 특히 유용합니다.

## 1. struct 모듈이 필요한 상황

텍스트(문자열) 기반 데이터는 사람이 읽고 쓰기 편하지만, 저장 공간이나 처리 속도, 또는 외부 시스템(C/C++/임베디드/네트워크 규격)과의 호환이 중요할 때는 바이너리 포맷이 선호됩니다. `struct`는 이런 바이너리 포맷을 파이썬에서 안정적으로 만들고 해석할 수 있게 해줍니다.

## 2. 주요 함수

- `struct.pack(fmt, v1, v2, ...)`  
  값들을 `fmt`(형식 문자열) 규격에 맞춰 `bytes`로 변환합니다.

- `struct.unpack(fmt, buffer)`  
  `buffer`(bytes/bytearray 등)를 `fmt` 규격에 따라 해석하여 튜플로 반환합니다.

- `struct.calcsize(fmt)`  
  `fmt`가 차지하는 바이트 수를 반환합니다.

- `struct.pack_into(fmt, buffer, offset, v1, v2, ...)`  
  이미 존재하는 버퍼(`bytearray` 등)의 `offset` 위치부터 값을 패킹해 넣습니다.

- `struct.unpack_from(fmt, buffer, offset=0)`  
  버퍼의 `offset` 위치부터 값을 언패킹합니다.

- `struct.Struct(fmt)`  
  포맷을 미리 "컴파일"한 객체를 만들 수 있어, 같은 포맷으로 반복 pack/unpack 할 때 성능과 가독성이 좋아집니다.

## 3. 형식 문자열(format string) 이해하기

형식 문자열은 크게 다음 두 부분으로 나뉩니다.

1) **바이트 오더(엔디안) 및 정렬 규칙 지정자**(옵션, 맨 앞 1글자)  
2) **데이터 타입 코드들**(필수)

### 바이트 오더 및 정렬 규칙(맨 앞 1글자)

- `@` : 네이티브 바이트 오더 + 네이티브 크기 + 네이티브 정렬(패딩 발생 가능)  
- `=` : 네이티브 바이트 오더 + 표준 크기 + 정렬 없음  
- `<` : 리틀 엔디안 + 표준 크기 + 정렬 없음  
- `>` : 빅 엔디안 + 표준 크기 + 정렬 없음  
- `!` : 네트워크 바이트 오더(빅 엔디안) + 표준 크기 + 정렬 없음

일반적으로 바이너리 포맷을 "항상 같은 방식"으로 만들고 싶다면 `<` 또는 `>`를 명시하는 것을 권장합니다.

### 자주 쓰는 타입 코드

- `x` : 패딩 1바이트  
- `c` : 1바이트 문자(bytes 길이 1)  
- `s` : 길이 N 바이트 문자열(반드시 `Ns`처럼 길이를 앞에 지정)  
- `p` : Pascal 문자열(`Np` 형태, 첫 1바이트에 길이 저장 후 데이터)  
- `?` : 불리언(1바이트)

정수형:
- `b` / `B` : 1바이트 signed/unsigned  
- `h` / `H` : 2바이트 signed/unsigned  
- `i` / `I` : 4바이트 signed/unsigned  
- `q` / `Q` : 8바이트 signed/unsigned  
- `n` / `N` : ssize_t / size_t (플랫폼 의존 크기)

실수형:
- `e` : 2바이트 부동소수점(float16)  
- `f` : 4바이트 부동소수점(float32)  
- `d` : 8바이트 부동소수점(float64)

기타:
- `P` : 포인터 크기(플랫폼 의존, 보통 `@`와 함께 쓰는 편)

반복/길이 지정:
- 숫자 접두사로 반복 횟수 또는 문자열 길이를 지정합니다.  
  예: `3I`는 `I` 3개, `16s`는 16바이트 문자열

## 4. 예제 코드

### 1) 정수와 실수 패킹/언패킹

```python
import struct

fmt = "<if"  # 리틀 엔디안: int32 + float32
data = struct.pack(fmt, 1, 2.3)

print(data)         # bytes 출력
print(data.hex())   # 16진수로 보기 좋게 출력

unpacked = struct.unpack(fmt, data)
print(unpacked)     # (1, 2.299999952316284) 처럼 보일 수 있습니다.
```

부동소수점은 이진 표현 한계 때문에 원래 값과 미세하게 달라 보일 수 있습니다.

### 2) 엔디안에 따른 바이트 차이 확인

```python
import struct

x = 42

print(struct.pack(">I", x).hex())  # 빅 엔디안
print(struct.pack("<I", x).hex())  # 리틀 엔디안
```

### 3) calcsize로 바이트 크기 확인

```python
import struct

fmt = "<Ih?"
print(struct.calcsize(fmt))  # 4 + 2 + 1 = 7 (정렬 없음)
```

### 4) pack_into / unpack_from로 버퍼에 직접 쓰고 읽기

```python
import struct

buf = bytearray(16)

struct.pack_into("<I", buf, 4, 42)   # offset 4부터 uint32로 42 기록
print(buf.hex())

value = struct.unpack_from("<I", buf, 4)
print(value)  # (42,)
```

### 5) Struct 객체로 반복 작업 최적화

```python
import struct

st = struct.Struct("<Ih?")
data = st.pack(100, -2, True)
print(data.hex())

print(st.unpack(data))  # (100, -2, True)
```

## 5. 리틀 엔디안과 빅 엔디안

엔디안(Endian)은 **여러 바이트로 이루어진 값**을 메모리에 저장할 때 **바이트를 어떤 순서로 배치하는지**를 말합니다.  
중요한 점은 **비트의 순서가 바뀌는 것이 아니라, 바이트의 나열 순서가 달라진다**는 것입니다.

- 리틀 엔디안(Little Endian): **하위 바이트(Least Significant Byte)** 를 먼저 저장합니다.  
- 빅 엔디안(Big Endian): **상위 바이트(Most Significant Byte)** 를 먼저 저장합니다.

## 6. 엔디안 예시

32비트 정수 `42`는 16진수로 `0x0000002A` 입니다.  
이를 4바이트로 나누면 다음과 같습니다.

- 바이트 단위: `00 00 00 2A`

메모리에 저장될 때:

- 빅 엔디안: `00 00 00 2A`  
- 리틀 엔디안: `2A 00 00 00`

파이썬으로 확인하면 다음과 같습니다.

```python
import struct

x = 42
print(struct.pack(">I", x).hex())  # 0000002a
print(struct.pack("<I", x).hex())  # 2a000000
```

값 `0x12345678`(32비트)를 생각해보겠습니다. 바이트로 나누면 `12 34 56 78` 입니다.

- 빅 엔디안 저장: `12 34 56 78`  
- 리틀 엔디안 저장: `78 56 34 12`

이때 하위 8비트(가장 작은 자리)는 `0x78` 입니다.  
리틀 엔디안에서는 하위 바이트가 **가장 낮은 주소(첫 바이트)** 에 위치합니다.

```python
import struct

x = 0x12345678

b_le = struct.pack("<I", x)
b_be = struct.pack(">I", x)

print(b_le.hex())  # 78563412
print(b_be.hex())  # 12345678

print(hex(b_le[0]))  # 0x78
print(hex(b_be[0]))  # 0x12
```

리틀 엔디안에서는 첫 바이트를 보면 바로 하위 8비트를 얻을 수 있어서 편리합니다.

이번엔 16비트 값 `0x1234`를 32비트 `0x00001234`로 확장한다고 하겠습니다.

- 16비트 값의 바이트:
  - 리틀 엔디안(16비트): `34 12`
  - 빅 엔디안(16비트): `12 34`

- 32비트로 확장했을 때의 바이트:
  - 리틀 엔디안(32비트): `34 12 00 00`
  - 빅 엔디안(32비트): `00 00 12 34`

즉, 리틀 엔디안에서는 "뒤쪽에 0이 붙는 형태"로 보이기 때문에 확장이 직관적으로 느껴질 수 있고, 빅 엔디안에서는 "앞쪽에 0이 붙는 형태"가 됩니다.
따라서 대부분의 현대 CPU(인텔, AMD, ARM 등)는 리틀 엔디안을 기본으로 채택하고 있습니다.

하지만 네트워크 프로토콜에서는 보통 빅 엔디안을 표준으로 삼고 이를 **네트워크 바이트 오더**라고 부릅니다.  
그래서 `struct`에서도 `!`를 사용하면 네트워크 바이트 오더(빅 엔디안)로 패킹/언패킹 할 수 있습니다.

```python
import struct

x = 0x12345678
print(struct.pack("!I", x).hex())  # 빅 엔디안과 동일하게 출력됩니다.
```

## 7. struct: 3줄 요약

- `struct`는 값과 바이트열(bytes)을 **정해진 규격(format string)** 으로 서로 변환합니다.
- 엔디안은 **멀티바이트 값의 바이트 배치 순서**를 의미합니다.
- 바이너리 포맷을 고정하고 싶다면 `<` 또는 `>` 같은 엔디안 지정자를 명시하는 습관이 좋습니다.
